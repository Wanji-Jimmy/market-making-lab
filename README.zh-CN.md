# 做市研究：库存、真实成交流量与报价

这个项目从库存管理开始，进一步研究：**过去五秒的主动买卖量，能否帮助预测随后五秒的价格？把这个预测加入报价，又会怎样改变库存、成交数量和盈亏？**

本项目使用 AI 辅助实现，方法、假设及复现步骤见本文。英文项目概览见 [README](README.md)。

当前版本已完成本轮研究范围。面试主线集中在“成交流量能否改善库存报价”；先理解账本、五秒特征、线性预测和对照结果。后面的原有情景、分钟与逐笔诊断作为辅助材料，不必在首次介绍里全部展开。

原有人工模拟仍然保留，参数没有用真实市场校准。新增研究使用真实历史成交训练预测模型，再放进明确假设客户意愿的报价实验；真实数据并没有使假设成交变成真实历史回测。

## 新研究怎样把真实数据接入报价

在决策时点 `t`，特征只来自 `[t−5秒,t)`：`I=(主动买入ETH量−主动卖出ETH量)/总量`。参考价是 `t` 之前最后一笔成交价，预测目标是下一格 `[t,t+5秒)` 末笔成交价的变化。只有相邻两格有成交才有标签；不填空格、不跨日，并报告参考价有多旧。标签可用性依赖未来是否有成交，并非当时可以用的信号。

训练日期固定为 **2025-09-01 至 09-03**，这些日期此前已经看过；**09-04 至 09-05** 用于验证但不选参数；**09-06 至 09-08** 用于冻结后的最终测试。模型只拟合 `预测变化=α+βI`，同时对比预测零和预测训练均值的基线，不能只看模型是否赚钱。

报价策略读取当前参考价、过去五秒特征、库存和冻结模型。完整策略在库存调整上加 `α+βI`，只有截距的对照只加 `α`，固定较宽价差对照则用于观察单纯改变成交参与程度的效果。报价信号限于 ±2 bp，中心移动还有包围参考价的限制，因此成交时相对参考价的优势非负，是模型设定。

下一格第一笔真实成交的方向只用于**未来模拟环境**，不传给报价策略。客户的价格底线由独立随机数生成；假设成交统一放在五秒格起点，没有重放那笔真实订单在格内的实际到达时刻。每天首个可用参考价归一化为 100，每次成交一个归一化单位，盈亏不是 USDT 实盘收入。

缺格时库存继续存在，价格缺口带来的重估进入盈亏；最后按最后一个可用标签价计算清仓成本，不假装恰好在午夜清仓。不同种子只是同一价格路径上的不同假设意愿，不能当作更多真实市场日期。测试只有三天，必须同时读每日和汇总结果。

本轮已跑完 **51,402 个测试样本、135 次策略实验**，离线复算与首次结果一致。模型相对预测零的平方误差约低 **0.51%**，但平均绝对误差约高 **10.55%**。在主要假设下，流量策略比库存策略平均多 **0.9203 个模拟货币单位**，三天中有一天变差，平均最大回撤也略有恶化。

更关键的是，降低客户意愿假设后，流量策略的相对盈亏优势反转。这轮研究把真实成交流量接进了报价，也暴露了模型依赖；没有把小幅预测改进包装成现实盈利。完整对照、账本分解与敏感性都保留在 [结果报告](flow_research_results/report.md)。

## 原有模拟里有三个角色

**市场环境**生成参考价、客户方向和客户的价格底线。环境可以生成客户掌握额外信息的情景，但策略看不到客户价格底线与下一步价格。

**报价策略**只读取当前参考价和自己的库存，报出愿买价格 bid 和愿卖价格 ask。

**账本**判断客户是否接受，随后更新现金和库存，最后按新的参考价估值。

每步先报价和成交，再发生下一步价格变化。先把整条外生市场路径生成好，交给两种策略分别运行；它们面对同样的客户机会，但因报价不同，实际成交可以不同。

## 原有模拟的两条报价规则

设当前参考价为 S，库存为 q，半价差为 h。

- A 固定价差：bid = S − h，ask = S + h。
- B 库存调整：报价中心 = S − kq，再在中心两侧减去／加上 h。

“固定”是价差宽度固定，参考价变化时仍会重新报价。默认 h=1、k=0.1。持仓偏多时B降低两个报价，较不愿继续买入，也较容易卖出。负库存时方向相反。

为了让首版保持清晰，偏移幅度限定在 h−tick 以内，并按价格最小单位舍入，保证买卖报价包围参考价。默认 tick=0.01。达到库存限额后，不能继续朝增加该方向风险的方向成交。所有限额、成本和报价网格对A/B一致。

## 客户什么时候成交

客户方向始终从客户视角命名：

- 客户 buy：只有 ask ≤ 客户最高愿付价格时才成交；做市商卖出一股。
- 客户 sell：只有 bid ≥ 客户最低愿收价格时才成交；做市商买入一股。
- 没有客户、价格谈不拢、库存超限或现金不足，都不会发生交易。

成交价格是做市商报价，不是客户最高／最低愿意支付的极限。每次只交易一股，手续费只在成交时收取。

## 钱究竟怎么变

设现金为 C，参考价为 S，库存为 q：账户总价值 V = C + qS。

买入一股，现金减去买价和费用，库存加1。卖出一股，现金增加卖价、扣除费用，库存减1。

我们每步都检查一个恒等式：

> 账户价值变化 = 成交相对旧参考价的优势 + 成交后库存 × 参考价变化 − 成交费用。

具体地，做市商买入的成交数量 Δq=+1，卖出 Δq=−1，成交价为 p：

> ΔV = Δq × (S − p) + q_after × (S_next − S) − fee。

没有成交时第一项和费用为0。采用成交后的库存，因为这次价格变化发生在成交之后。

教学账本从1000现金、2股、参考价100开始，初始总价值1200。五个事件后，成交相对参考价的优势累计为+2.70，库存价格变化贡献−6.00，无手续费，账面盈亏−3.30。再按假设成本清掉最后1股，盈亏为−4.30。这些是确定事件的算术结果，不是随机绩效。

## 原有模拟的随机市场假设

这一部分的数值是人工场景，不是当前行情、真实客户报价或实证校准。一个“步”是抽象事件时间，没有对应一秒或一天，不计算年化收益或年化Sharpe。

普通客户以默认0.8概率到达，买卖方向各半；最高愿付／最低愿收价格是参考价加／减一个正的交易意愿量。默认意愿量服从均值1.5的指数分布。敏感性检查改用同均值均匀分布。

价格从100开始，每步加上高斯变化和可选跳跃；价格按0.01网格变化，并设置正价格下界。默认低波动标准差0.2，高波动1.2。单边压力同时改变客户方向比例与价格漂移，不能用这种联合情景单独识别某一个因素的因果效果。

知情客户的价格底线与下一次价格变化加少量噪声相关。环境用这种构造制造逆向选择：客户可能在上涨前向你买、在下跌前卖给你。报价函数始终看不到未来。这是人为压力场景，不是说真实客户都知道未来。

## 怎样读结果

主统计表使用**扣除期末清仓成本后的盈亏**；逐步曲线显示清仓前按参考价估值的盈亏，页面分别标注。

- 平均盈亏：总体收入表现，可能掩盖很差的路径。
- 亏损比例：有多少条模拟路径最终亏损。
- 最差5%平均盈亏：排序后最差的一组路径；主实验500条时取25条。
- 平均绝对库存：通常承担多少方向性持仓。
- 成交数量：库存更小是否与成交变化同时发生。
- 配对B−A：同一条市场路径中B比A多赚或少赚多少，再对差值取均值。

配对均值区间为均值±1.96×模拟标准误，是该模型内的近似蒙特卡洛误差；不包含模型错误、不证明真实市场盈利，也不把同一模型的新随机种子称作真实样本外数据。

## 真实公开数据：从成交记录看交易之后的价格

这部分使用交易所官方历史记录，与上面的人工模拟分开运行：

| 模块 | 数据 | 研究问题 |
| --- | --- | --- |
| `real_data.py` | ETHUSDT，2025-09-01 至 09-03，聚合成交 | 一分钟内主动买入较多，下一分钟还会上涨吗？ |
| `tick_data.py` | ETHUSDT，2025-09-01，未聚合逐笔成交 | 主动买入或卖出之后，1、5、30 秒的成交价怎样变化？ |

`aggTrades` 的一行可能合并多笔成交；`trades` 保留每个成交 ID，但同一客户订单仍可能拆成多笔。逐笔模块会把数量、成交额、ID 范围和逐分钟统计与聚合文件对账，避免把两种数据的“行数”混为一谈。

```bash
python3 real_data.py
python3 tick_data.py
# 完整缓存下载后，可以不联网复算：
python3 tick_data.py --offline
```

不需要账户或 API key。程序从 Binance 官方公开归档下载 ZIP，核对官方 SHA256；原始文件留在本地，不上传 GitHub。字段、微秒时间戳、买卖方向、异常数据和时间匹配都有检查。

逐笔诊断中，主动买入记 +1、主动卖出记 −1，再乘以后续成交价变化。比如主动买入价 100，5 秒后的匹配成交价是 100.02，方向调整后的变化就是 +2 bp；主动卖出 100、后续变成 99.98，也得到 +2 bp。正数表示行情向主动成交者有利的方向走。

我们匹配目标时点之后的第一笔成交，允许最多晚 1 秒，并报告实际延迟；不会假装每个目标时点都恰好有成交。无法匹配和跨日的窗口排除，各期限使用自己的有效样本数。三个期限分别约有 4.75%、5.67%、6.06% 的事件仅因查找延迟过长被排除；因此结果可能偏向较活跃的交易状态。这种根据未来成交是否出现所做的筛选，在事件当时并不知道，不能当成实盘入场条件。

先读[逐笔诊断中文结果](tick_data_results/研究结果.md)，再看[完整方法](docs/TICK_DATA_DIAGNOSTIC.md)。这一天原先的分钟结果已经看过，因此它是探索性分析，不能叫作未见过的测试数据。成交价也不等于中间价；这个模块帮助研究成交后的价格风险，还不能说明我们的挂单会成交或真实策略会盈利。

## 最重要的模型局限

报价包围参考价，意味着每次成交相对旧参考价的“成交优势”被限制为非负；普通客户意愿又与未来价格独立。因此平衡情景中的正收益部分来自模型设定。损失会通过持仓价格变化、费用和清仓体现。必须连同知情客户和高费用压力一起读结果。

没有完整订单簿、排队、其他做市商、市场冲击、延迟、借券费和保证金；期末平仓采用固定摩擦成本估算，不模拟真实大单清仓。模型只能帮助检验清楚列出的假设。

成交数量变化要与利润和库存一同解释。这一版没有强行匹配两种策略的成交数量，因此不能仅凭风险降低就宣称完全分离了“少成交”的影响。
