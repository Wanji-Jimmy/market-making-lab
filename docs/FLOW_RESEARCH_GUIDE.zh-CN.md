# 从真实成交流量，到一个可以检验的报价想法

这一轮要回答两个不同的问题：**过去五秒主动买入较多，能否帮助预测随后五秒的成交价变化？把这个预测用于调整报价，在我们的模拟成交规则下又会怎样？** 预测有效，不自动意味着做市策略有效；模拟赚钱，也不能反过来证明预测有效。

研究约定在 [FLOW_SIGNAL_PLAN.json](../research/FLOW_SIGNAL_PLAN.json)。实际数字和执行状态以 [本轮研究结果](../flow_research_results/report.md) 为准，这份讲解不预设项目会得到正结果。

## 1. 先明确我们看到了什么

数据来自 ETHUSDT 的真实公开聚合成交记录。每条记录有价格、数量、时间和买方是否为 maker 等字段。

maker 是被动挂单的一方。`isBuyerMaker=true` 意味着买方被动、卖方主动；这一笔计入主动卖量。反之计入主动买量。这里测量的是**已发生的主动买卖成交量**，不是尚未成交的订单簿买卖盘数量。

以决策时点 12:00:05 为例：

| 内容 | 使用的信息 |
|---|---|
| 特征 | 12:00:00 ≤ 时间 < 12:00:05 的主动买卖量 |
| 当前参考价 | 12:00:05 之前最后一笔成交价 |
| 预测目标 | 12:00:05 ≤ 时间 < 12:00:10 内最后一笔成交价相对参考价的变化 |

恰好在 12:00:05 发生的成交属于后一个区间，不能提前放进当前特征。参考价是**最后成交价**，数据没有告诉我们当时真实的买卖报价中间价。

如果过去五秒主动买入 9 ETH、主动卖出 1 ETH，成交流量不平衡为：

```text
I = (买量 − 卖量) / (买量 + 卖量)
  = (9 − 1) / (9 + 1)
  = 0.8
```

`I=1` 表示这一格全是主动买入，`I=−1` 表示全是主动卖出，`I≈0` 表示双方成交量接近。这并没有告诉我们接下来一定涨跌。

只有相邻两格都有成交，才得到这一行完整的预测标签。缺格不补旧价格，不跨日拼标签。报告同时记录缺格数量及参考价距离决策时点有多旧，不能把留下来的样本当成全部市场时刻。下一格是否有成交属于未来信息，这一筛选只是标签可用性条件，不是报价时已知的信号。

## 2. 用训练数据估计一条很简单的关系

模型只有一条直线：

```text
预测的随后五秒变化（bp） = α + β × I
```

1 bp 是 0.01%。`α` 是不平衡为零时模型预测的变化；`β` 表示不平衡增加 1 时，模型预测变化增加多少 bp。OLS 会在训练数据上选取使平方误差总和最小的 `α` 和 `β`。

模型的原始预测保留用于评估；输入报价规则的预测另限制在 −2 至 +2 bp。这是事先写下的限制，不能看完测试结果再换成更好看的值。

我们必须比较两个简单预测基线：每次都预测零，以及每次都预测**训练集的平均变化**。只说模型“方向正确率超过一半”不够。MSE 对大错误更敏感，MAE 看平均绝对错误，两者可能给出不同评价。

方向指标排除实际变化恰好为零的样本；在实际变化非零时，预测零按未猜对计算，同时单独报告方向覆盖率。因此零预测基线方向正确率、覆盖率都是零，不能仅凭这一指标宣称模型战胜了基线。

## 3. 把预测放进报价，而不是直接下一个方向赌注

报价中心同时受到库存和预测影响：

```text
库存调整（bp） = −0.2 × 当前库存
信号调整（bp） = 截断到 [−2, +2] 的模型预测
中心总调整（bp） = 库存调整 + 信号调整
报价中心 = 当前参考价 × (1 + 中心总调整 / 10,000)
```

库存为正，意味着手里持有资产，库存项让中心下降，鼓励卖出、减少继续买入。预测价格上涨，则信号项让中心上升。两个动机可以互相抵消。

下面是**人为指定系数的算术例子，不是实际拟合结果**：

```text
参考价 P = 100，库存 q = 3
假设 α = 0，β = 0.3，刚观察到 I = 0.8

库存调整 = −0.2 × 3 = −0.6 bp
信号调整 = 0 + 0.3 × 0.8 = +0.24 bp
合计调整 = −0.36 bp

报价中心 = 100 × (1 − 0.36 / 10,000) = 99.9964
半价差 = 100 × 2 / 10,000 = 0.02
理论买价 = 99.9964 − 0.02 = 99.9764
理论卖价 = 99.9964 + 0.02 = 100.0164
```

标准规则是**半价差 2 bp**，所以完整买卖价差约为 4 bp。报价按 0.0001 的价格格点向外取整：买价向下、卖价向上。本例理论价格恰好落在格点上。

代码还限制中心移动幅度，让报价始终跨在参考价两边。这个约束使成交时相对参考价的价格优势非负，是模型设定，并不证明找到了现实中的无风险收益。成交后的价格变化和费用仍然可能让账户亏损。

## 4. 为什么需要五个策略

| 策略 | 报价中心 | 半价差 | 用来检验什么 |
|---|---|---:|---|
| `fixed` | 参考价 | 2 bp | 基本固定价差报价 |
| `inventory` | 加库存调整 | 2 bp | 只控制库存的基线 |
| `constant_wide` | 加库存调整 | 3 bp | 单纯加宽价差、改变参与程度的效果 |
| `flow` | 加库存调整、完整预测 `α+βI` | 2 bp | 主要候选策略 |
| `intercept_only` | 加库存调整、只有 `α` | 2 bp | 完整策略的效果是否来自不平衡项 `βI` |

`α` 不一定等于训练集的平均收益：当训练集平均 `I` 不为零时，两者可以不同。`intercept_only` 是报价策略对照，训练均值则是预测误差的基线，不能混为一谈。

主要比较 `flow − inventory`，并用 `flow − intercept_only` 检查不平衡项的增量作用。还要同时看成交数、参与比例、库存、费用和回撤。假设利润改善只是因为几乎不成交了，这和在相近参与程度下改善交易质量，是不同的结果。

## 5. 哪些是真实的，哪些仍然是假设

真实部分包括历史成交价格、数量、时间和主动方向。每个可用的下一格中，第一笔真实成交的主动方向，被用于指定一个**假设客户**的买卖方向。

假设部分包括这个客户是否愿意接受我们的报价：程序用一个独立随机数生成其可接受价格范围，每格最多给一次假设交易机会。数据没有提供这个客户真实的价格底线，也没有证明我们的订单能排到队、能够成交。

报价函数只能看当前参考价、过去五秒不平衡、自己的库存和已经冻结的模型。它看不到下一格价格、未来客户方向或客户底线。模拟环境在报价后使用这些信息判断事件，不能把环境字段传进策略当成特征。

不同策略面对同一套预先生成的客户机会和随机数。换随机种子只是在**同一条历史价格路径上改变假设客户意愿**，并没有得到更多独立的真实交易日。不能把大量种子当作大量市场样本来计算看似精确的置信区间。

每个交易日的首个可用参考价归一化为 100，成交数量是一个归一化单位。因此盈亏是模型货币单位，不是赚到的 USDT，也不是可以照搬到实际账户的回报。

遇到缺格时，系统不能假装库存消失：期间不提供客户机会，但库存要从上一个已观察价格重估到下一个可用价格，缺口损益也进入账本。最终在最后一个可用标签价计入清仓成本，不声称恰好在 UTC 午夜完成交易。

## 6. 怎样避免看完答案再修改问题

本轮约定的日期划分是：

| 用途 | UTC 日期 | 允许做什么 |
|---|---|---|
| 训练 | 2025-09-01 至 09-03 | 估计 `α`、`β`，计算训练均值；这些日期此前已被查看过 |
| 验证 | 2025-09-04 至 09-05 | 检查冻结方法的表现，报告问题；本轮不据此选择模型或参数 |
| 测试 | 2025-09-06 至 09-08 | 模型、规则和代码冻结后进行最终评价 |

流程要求在下载未见日期前公布计划，保存模型、源代码哈希和开发数据校验信息；测试阶段先核对冻结内容，再获取测试数据。这样可以检查最终展示的结果是否确实来自事先确定的规则。

这不是一份正式注册的学术研究，而且测试只有三个交易日。看完测试结果之后，这些日期就已经是“看过的数据”。如果发现错误，需要记录修正，不能修完后把同一批数据重新称为未见测试；新的研究想法应当配新的计划和新日期。

最终结果可能是预测误差改善但模拟盈亏恶化，也可能两者都没有改善。完整保留这些结果，本身就是研究的一部分。请直接阅读 [本轮研究结果](../flow_research_results/report.md)，不要只挑一行利润最大的策略。

## 7. 你理解这个项目之后，应该能亲自回答

先做下面几项独立检查，而不是背诵项目介绍：

1. 手算买量 9、卖量 1 的不平衡，并解释为什么买方是 maker 时记为主动卖出。
2. 给定一笔恰好发生在 12:00:05 的成交，判断它属于哪个五秒格，能否用于 12:00:05 的报价。
3. 只修改下一格的价格和买卖方向，确认当前 `imbalance`、参考价和报价不会跟着偷变；解释哪些输出应当变化。
4. 用上面的例子算报价，再把库存从 3 改成 −3，判断中心移动方向。
5. 解释为什么 MSE 下降时 MAE 仍可能上升，以及这为何不直接等于策略赚钱。
6. 找出 `flow` 与 `intercept_only` 的唯一区别，解释为什么这个对照值得保留。
7. 对照一次模拟账本，把成交价格优势、库存价格变化、缺格重估、手续费和清仓成本加回总盈亏。
8. 指出要验证现实中的挂单成交，还缺哪些订单簿、排队和执行数据。

核心阅读入口是 [flow_data.py](../flow_data.py)：先看 `build_day_rows` 的时间边界，再看 `fit_ols`、`predict` 和 `forecast_metrics`。测试用例 [test_flow_data.py](../test_flow_data.py) 提供了可以手算的边界和小样本。

这个版本包含 AI 协助实现和审查。当前有代码，不等于你已经独立掌握所有内容。对外介绍时，可以如实说明自己参与确定了什么问题、理解并验证了哪些假设、亲自修改或检查了什么，再准确描述 AI 协助的部分。尚未亲自完成的工作不要写成自己的独立贡献；面试时能够解释一项真实做过的检验，比背诵一串技术名词更有说服力。
